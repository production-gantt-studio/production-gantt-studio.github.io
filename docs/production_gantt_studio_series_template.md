# Production Gantt Studio — 業務支援ツールシリーズの参照テンプレート

> **結論**：今後の業務支援ツールは、Production Gantt Studioの「制作現場で迷わせない情報設計」と「淡色の作業面に濃色サイドバーを組み合わせる画面骨格」を出発点にする。ただし、画面を似せるだけでは不十分である。案件分離、保存、権限、閲覧専用、操作時の状態遷移を参照元と同じように生かす。

## 1. 適用範囲と真実の基準

この文書は、今後作る制作進行、見積、発注、撮影管理、イベント運営、校正、素材管理などの**業務支援ツールシリーズ**に適用する。参照元は次の順で扱う。

| 優先度 | 真実の基準 | 用途 |
|---|---|---|
| 1 | 現行ソース `client/src/pages/`、`client/src/lib/`、`server/`、`drizzle/` | 操作、保存、権限、状態遷移、データ境界 |
| 2 | `client/src/index.css`、`client/src/simplify.css` | 色、余白、文字、固定列、モバイル、印刷 |
| 3 | 現行の公開画面と検証スクリーンショット | 最終の視覚比較 |
| 4 | `docs/` 配下のレビュー、移行、運用資料 | 仕様判断、受入条件、未実装の将来構想 |

スクリーンショットは最終比較用であり、再利用する素材ではない。新しいツールでは、現行ソースの構造・ライブデータ・操作可能な部品を参照し、静的な見せかけへ置換しない。

## 2. シリーズ共通の利用者体験

### 2.1 目的

このシリーズは、現場担当者が朝に開いたとき、次の三点を短時間で把握できることを目的にする。

1. **いま何が進んでいるか**
2. **次に誰が対応するか**
3. **どの案件・項目に注意が必要か**

機能数を増やすことは目的ではない。利用者が専門知識や長いマニュアルなしに、一覧から対象を開き、その場で必要な情報を変更できることを優先する。

### 2.2 画面の基本骨格

| 領域 | 役割 | Production Gantt Studioでの基準 |
|---|---|---|
| 左サイドバー | 現在地、主要導線、利用者情報 | 濃いグラファイト背景。案件／機能を短いラベルで並べる。 |
| 上部バー | ページ名と最重要アクション | 主導線は右上に一つ。補助操作は増やしすぎない。 |
| メイン作業面 | 一覧、タイムライン、編集対象 | 明るい淡灰背景と白い作業面。内容を横長に扱う。 |
| インサイト領域 | 次の行動を促す情報 | 期限、未担当、確認待ち、引継ぎなど、行動に直結する情報だけ。 |
| 設定・補助操作 | 低頻度の詳細操作 | 「設定」「その他」へまとめ、日常の主導線を邪魔しない。 |

各ツールはこの骨格を基準にするが、内容領域は業務に合わせて変えてよい。たとえば見積管理ならタイムラインの代わりに見積行、素材管理ならプレビューと承認状況を置く。どの場合も、案件一覧→対象画面→その場で編集という流れを保つ。

## 3. デザインシステム

### 3.1 色と文字

ライトモード専用とする。将来ツールにダークモードの切替を追加しない。全ツールで以下を基調にする。

| 用途 | 基準値・扱い |
|---|---|
| 背景 | `#f4f5f4` または近い淡い無彩色 |
| 作業面 | 白 `#ffffff` |
| 主要文字 | 濃紺灰 `#17212b`〜`#1b2530` |
| 補助文字 | 灰青 `#74808b` |
| サイドバー | グラファイト `#202932` |
| 主アクション | ライム `#c7f36b`。背景が濃い場面でだけ使う。 |
| 罫線 | 薄い灰 `#dbe0df`〜`#e5e9e8` |

日本語本文は `Noto Sans JP`、数字・英字の表示見出しは `Space Grotesk` を基本とする。大きな見出しは力強く、補助ラベルは小さく密度を落とす。装飾目的のグラデーション、ネオン、過度な影、丸いカードの乱用は避ける。

### 3.2 状態色の固定ルール

意味のある状態色は、全ツールで次の4色＋中立色に限定する。業務に応じてラベルは変えてよいが、色の意味を反転させない。

| 色 | 意味 | 例 |
|---|---|---|
| 赤 `#c9232d` | 危険、重要、期限超過、要対応 | 重要日、失敗、警告 |
| 黄 `#b77916` | 確認待ち、判断待ち | 承認待ち、クライアント確認 |
| 緑 `#287a5e` | 完了、承認済み、安全 | 完了、納品済み |
| 青 `#3976c7` | 進行中、修正中、作業中 | 作業中、差し戻し対応 |
| 灰 | 未着手、中立、情報不足 | 未設定、保留ではない初期状態 |

色だけに意味を持たせない。状態名、アイコン、明確なコントラストを併用する。赤い重要情報は淡色でぼかさず、白地または濃色地で判読できるようにする。

### 3.3 操作感

- 高頻度の操作は行内・画面内で完結させる。別画面やモーダルを無条件に増やさない。
- 破壊的操作は確認を出し、復元可能な設計を優先する。
- 保存状態、権限不足、未設定を曖昧な表示にしない。
- ボタンは何を起こすかを具体的に書く。例：`＋ タスク`、`新規案件`、`復元`。
- キーボード・フォーカス状態を見えるようにする。
- モバイルでは主要情報を先に見せ、幅が足りないデータ領域は横スクロールを許容する。

## 4. 機能設計の共通原則

### 4.1 一覧から始め、対象を隔離する

業務支援ツールの入口は、利用者に見せてよい対象だけを並べる一覧とする。プロジェクト、案件、発注、素材などの単位が何であっても、他人・他社・他案件の情報を混ぜない。

| 原則 | 実装要件 |
|---|---|
| 対象分離 | データ取得時に所有者・メンバー・組織を検証する。URLのIDだけを信頼しない。 |
| 閲覧専用 | 見せる必要がある対象だけを出し、編集導線を表示しない。 |
| 作成制限 | 新規作成者を明確にする。必要なら管理者だけに限定する。 |
| 保存 | 画面上の変更と保存先を一致させ、保存失敗を隠さない。 |
| 削除 | 即時消去ではなく、アーカイブと復元期間を基本とする。 |

### 4.2 アラートは通知ではなく次の行動

アラートは情報を増やすためではなく、利用者が次に開くべき対象を決めるために使う。通常時は一行の要約にし、問題があるときだけ内容を展開する。メール通知や外部通知は、実際の運用責任者と宛先が決まるまで追加しない。

### 4.3 データと表示を混同しない

画面に表示する数値・進捗・状態はライブデータから出す。存在しない顧客レビュー、評価、実績、ユーザー数、成功率をサンプルでも表示しない。空の状態は、次の操作が分かる誠実な案内にする。

## 5. 参照再現の境界

### 5.1 必ず保持するもの

1. 視覚階層：濃色サイドバー、白い作業面、明確な主導線、情報量の抑制。
2. 色の意味：赤・黄・緑・青の役割と灰の中立性。
3. 操作原則：その場で編集、補助操作の集約、誤操作の復元、権限に応じた表示。
4. 安全境界：対象分離、閲覧専用、保存、アーカイブ、権限検証。
5. 品質基準：型検査、単体テスト、本番ビルド、画面確認、実操作確認。

### 5.2 業務ごとに変えてよいもの

- 中央作業面の情報構造。
- フェーズ、タスク、素材、申請、見積などのドメイン名。
- 業務に必要な入力項目と状態名。
- 業務上必要な承認・コメント・出力機能。

### 5.3 変えてはいけないもの

- 見せてはいけない他案件・他社データが表示されること。
- 閲覧者が編集できること。
- 動く機能を静的表示や偽のボタンに置き換えること。
- エラーや保存失敗を成功したように見せること。
- テスト・画面確認なしに「完全」「問題なし」と報告すること。

## 6. 新ツール着手時に作る参照マニフェスト

新しいツールごとに、実装を始める前に次の表を作る。

| 項目 | 記入内容 |
|---|---|
| ツール名・目的 | 誰が、いつ、何を判断・更新する道具か |
| 参照元 | Production Gantt Studioのソース、画面、業務仕様のどれを使うか |
| 維持するライブ機能 | 保存、権限、対象分離、復元、共有など |
| 業務固有の変更 | 中央作業面、入力項目、状態、出力の差分 |
| 未実装・保留 | 現時点で作らない機能と理由 |
| 受入証跡 | テスト、画面確認、操作確認、承認者 |

## 7. リリース前のデザイン判定

新ツールのデザインは、以下の全条件を満たしたときだけ「ユーザー確認可能」と報告する。

| 観点 | 判定基準 |
|---|---|
| 情報階層 | 初見で、現在地・主操作・注意対象が分かる。 |
| 色 | 赤・黄・緑・青の意味が逆転せず、文字が読める。 |
| 操作 | 高頻度操作が深い詳細画面に閉じ込められていない。 |
| 権限 | 閲覧者に編集操作が出ず、対象分離が確認できる。 |
| 保存 | 実データの変更・復元・失敗表示を確認した。 |
| モバイル | 主要情報が潰れず、必要な横スクロールが機能する。 |

**判断の基準は「似ているか」ではなく、「参照ツールが守っている利用者の判断・操作・安全を、新しい業務でも同じ水準で守れているか」である。**
