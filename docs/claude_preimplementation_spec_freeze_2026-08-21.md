# Claude実装前：仕様凍結と差分0件確認プロンプト

> **使い方**：Production Gantt Studioの専用Claudeプロジェクトへ、ソース一式と最終実装引き継ぎ資料を追加した後、この文書の「Claudeへ送る本文」だけを最初のチャットに貼り付ける。
>
> **重要**：この段階でClaudeはコードを書かない。先に現行アプリの仕様を読み切り、受入条件を固定する。利用者が確認する前に実装を始めない。

## Claudeへ送る本文

```text
Production Gantt Studioを忠実に再実装する前の、仕様凍結レビューを開始してください。

このメッセージでは、コードを書かないでください。画面だけの試作品、機能を省いた代替案、技術を勝手に置き換える提案も出さないでください。

まず、追加済みの現行ソース、テスト、docsをすべて読み、次の4つをMarkdownで提出してください。

1. 仕様マニフェスト
   画面、案件作成、テンプレート、ガント、依存関係、親子タスク、アラート、権限、共有、招待、保存、アーカイブ、Q&A、セキュリティ、費用、テストの全項目を1行ずつ表にしてください。
   各行に「現行根拠ファイル」「守る動作」「保存・権限への影響」「受入条件」「状態」を書いてください。
   状態は「保持」「要確認」「承認済み変更」だけを使ってください。

2. 差分表
   現行ソースと資料の間、または資料同士で違いがある場合だけ、差分を表にしてください。
   推測で解決しないでください。差分は「要確認」とし、実装を始めないでください。

3. 実装順と受入証跡表
   仕様を壊さない小さな実装単位へ分け、各単位に「変更ファイル」「自動テスト」「型検査」「本番ビルド」「デスクトップ確認」「モバイル確認」「権限・保存確認」を書いてください。

4. 実装開始判定
   「保持」が全項目に付いているか、「要確認」が残っていないかを明記してください。
   要確認が1件でもある場合は、結論をHOLDにしてください。

以下は必ず保持する非退行条件です。
- 最初の画面は案件一覧である。
- 案件を作れるのはログインした管理者だけである。
- 管理者、編集者、閲覧者の権限を、画面とサーバーの両方で守る。
- 共有は1案件だけの閲覧専用で、期限・停止・再発行・アクセス記録を持つ。
- 共有URLに案件データや秘密情報を入れない。
- 削除は30日アーカイブと復元を持ち、30日後だけ削除対象にする。
- 日程・依存関係・親子タスク・Undo・日週月表示・固定列・アラート・PDF・CSV/JSON・Q&Aを省略しない。
- ライトモードのみとし、色の意味を赤・黄・緑・青で固定する。
- 高・中の既知脆弱性を0件に保ち、権限、CSRF、Origin制限、HTTP保護、監査ログを緩めない。
- 利用者のAPIキー入力、利用者ごとの従量課金、未承認の外部サービスを標準機能に入れない。

利用者の確認前に、実装、コード生成、依存関係の追加、設計変更を始めないでください。
提出するのは、上記4つのMarkdown資料だけです。
