# データを守る標準運用：自動バックアップなしで始める場合

**対象読者**：Production Gantt Studioを使う制作会社、社内管理者、案件の責任者です。技術知識は必要ありません。

> **結論**：通常のログイン案件はアプリのデータベースに保存されます。ブラウザを閉じただけで案件が消えることはありません。ただし、自動バックアップは標準では使いません。大切な案件は、案件責任者が設定画面からJSONを書き出して保管してください。この操作には利用者のAPI設定や追加料金は必要ありません。

## 1. 標準の保存方法

| 保存場所 | 何が入るか | どの端末から見えるか | 消える主な条件 | 復旧の考え方 |
|---|---|---|---|---|
| ブラウザ内の一時保存 | ログイン前の案件、操作途中の内容 | 同じブラウザ・同じ端末だけ | ブラウザのデータ削除、シークレット画面の終了、端末交換 | 重要案件はログイン後に保存する |
| アプリのデータベース | ログイン後に保存した案件、メンバー、変更履歴 | 権限を持つ利用者の端末 | 管理者が案件を削除し、アーカイブ期間が過ぎた場合。運営基盤の障害・誤操作は別途対応が必要 | アーカイブ期間内は復元。JSON書き出しがあれば再取り込みできる |
| 共有リンク | 閲覧用の入口だけ。案件本体の複製ではない | リンクを渡した相手 | リンクの期限切れ、管理者による失効 | 新しい閲覧リンクを発行する。案件データ自体は消えない |
| 管理者が保存したJSONファイル | 案件データの控え | ファイルを保管した場所 | ファイルを消した、壊した、上書きした | 同じJSONを設定画面から取り込む |

## 2. データが消える、または見えなくなる条件

### ブラウザだけで使っている案件

ログインせずに作った案件は、作成したブラウザの中にだけ保存されます。そのブラウザで「サイトデータを削除」した場合、シークレット画面を閉じた場合、別のPC・スマートフォンへ移った場合は、同じ案件を開けません。これは端末内のメモ帳にだけ書いた内容と同じです。

**対策**：案件を続けて使うと決めた時点でログインして保存してください。ログイン後は、編集できるメンバーだけが案件を開けます。

### ログインして保存した案件

ログイン案件はアプリのデータベースへ保存されます。ブラウザの履歴削除、ブラウザの更新、端末の変更、共有リンクの失効だけで案件本体が消えることはありません。

ただし、管理者が案件を削除した場合はアーカイブへ移ります。**30日を過ぎるとアーカイブ案件は自動的に削除対象**です。また、JSONを取り込む際に同じ案件の内容を上書きする操作をした場合、取り込み前の内容はその操作だけでは戻せません。

**対策**：削除前にはアーカイブで確認し、重要案件の大きな変更前・納品前・引継ぎ前にはJSONを1つ書き出してください。

### 共有リンク

共有リンクは案件を読むための一時的な鍵です。期限が過ぎた、または管理者が失効させた場合、リンクを開いても案件は見えません。これは案件の削除ではありません。編集者または管理者が新しいリンクを作れば、同じ案件を再度共有できます。

## 3. 月1回・納品前に行う操作

| いつ | 案件責任者が行うこと | 目的 |
|---|---|---|
| 月に1回 | 設定画面からJSONを書き出す | 誤操作や端末変更に備える |
| 大きな日程変更の前 | JSONを書き出す | 変更前の状態を残す |
| 納品・完了時 | JSONを書き出し、案件名と日付を付けて保管する | 後日の確認・再利用に備える |
| 案件を削除する前 | アーカイブへ入ることを確認し、必要ならJSONを書き出す | 30日後の自動削除に備える |

JSONは案件データを含むため、公開チャットや不特定多数が見られる場所には置かないでください。案件責任者が管理するPCや、会社がすでに使っているアクセス制限付きの保管場所に置きます。

## 4. 困ったときの復旧手順

### 間違って案件を削除した

案件一覧の**アーカイブ**を開き、対象案件の**復元**を選びます。30日以内であれば、元の案件一覧へ戻せます。

### 端末を変えた、またはブラウザの内容が消えた

ログインしていた案件は、同じメールアドレスでログインすれば表示されます。ログイン前に作った案件だけは、新しい端末へ自動移行されません。残していたJSONがあれば設定画面から取り込めます。

### 共有リンクが開けない

案件本体が消えたわけではありません。管理者または編集者に、新しい閲覧リンクの発行を依頼してください。

### JSONを取り込んだら内容が違う

取り込み前に書き出したJSONがあれば、そのファイルを再度取り込みます。書き出しがない場合は、案件の変更履歴とアーカイブを確認します。

## 5. 将来の自動バックアップについて

自動バックアップは、利用者がAPIキーを入力する仕組みではありません。しかし、保存容量や定期実行のために**販売側へ費用が発生する可能性**があります。そのため現行の標準構成には含めません。

将来導入する場合は、導入前に「誰に費用が発生するか」「月額・従量課金の可能性」「保存期間」「復旧できる範囲」を利用規約と販売資料へ明記し、販売責任者の承認を受けます。利用者へ追加費用が発生する方式は、利用者本人が明示的に選んだ場合だけ採用します。

## 6. このガイドの確認結果

| 確認項目 | 現行の扱い |
|---|---|
| 利用者のAPI設定 | 不要 |
| 利用者ごとの追加課金を前提とする自動バックアップ | 不採用 |
| 削除案件の猶予 | 30日間のアーカイブ |
| 共有リンクの安全性 | 期限・失効・アクセス記録を持つサーバー側トークン |
| 重要案件の控え | 案件責任者がJSONを書き出して保管 |
| 自動バックアップ | 将来の費用・保存期間を事前承認できた場合のみ検討 |
