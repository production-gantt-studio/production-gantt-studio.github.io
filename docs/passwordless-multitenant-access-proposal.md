# メール認証の編集者とゲスト閲覧者を分ける販売可能なアクセス設計

> **推奨結論**：編集者は、招待されたメールアドレスへ送る一回限りのログインリンクで入る。パスワードは作らない。閲覧者は、案件ごとに発行したゲストURLで入る。組織・案件・ライセンスはサーバー側で分け、案件一覧には「自分が作成した案件」と「自分が招待された案件」だけを出す。

| 設計対象 | 決めること |
| --- | --- |
| 編集者の認証 | メールアドレス入力 → メール内リンクを押す → ログイン完了。パスワード不要。 |
| 閲覧者 | ゲストURLで閲覧する。ログイン不要、編集不可、案件の変更ログは閲覧可。 |
| 案件作成 | 組織管理者だけが作成する。編集者は案件を勝手に新規作成できない。 |
| 案件一覧 | 自分が作成した案件と、自分が編集者として招待された案件だけを表示する。 |
| 販売 | 購入企業ごとに組織（テナント）を分け、契約と利用上限を組織単位で持つ。 |
| 現在の状態 | **未実装の将来仕様**。現行のブラウザ内保存・共有URLを置き換える。 |

## 0. 新規案件ボタンの表示対象を現行版と認証版で分ける

現行版にはログイン・組織・権限の判定がない。そのため、通常画面で案件データを開いた利用者には **「新規案件」** ボタンが表示される。一方、閲覧共有URLで入った閲覧者には、案件作成、設定、編集の導線を表示しない。

認証版では、この表示条件を次のように置き換える。案件を新しく作る権限は **組織管理者** だけに与え、ボタンも組織管理者にだけ表示する。初期導入時は、初期管理者である導入責任者を唯一の組織管理者にする。編集者は招待された案件を編集できても、任意に別案件を増やせない。

| 利用状態 | 「新規案件」の表示 | 案件作成 |
| --- | --- | --- |
| 現行版の通常画面 | 表示する | 可能。認証・権限判定は未実装。 |
| 現行版の閲覧共有画面 | 表示しない | 不可。 |
| 将来の認証版：組織管理者 | 表示する | 可能。 |
| 将来の認証版：編集者 | 表示しない | 不可。招待済み案件の編集のみ。 |
| 将来の認証版：閲覧者 | 表示しない | 不可。 |

## 1. 編集者のログインは「パスワードなし・メール確認あり」にする

「メールアドレスだけで入る」とは、アドレスを入力しただけで即時に編集可能にする意味ではない。本人以外が他人のアドレスを入力して編集できてしまうためである。編集者には、入力したメールアドレスの受信箱へ**一回限りの確認リンク**を送る。リンクを押した時点で、そのメールアドレスの利用者としてログインする。

これは一般に **マジックリンク認証** と呼ばれる。利用者はパスワードを作成・記憶・再設定する必要がない。一方、編集の本人確認はメール受信箱の保有で行う。
