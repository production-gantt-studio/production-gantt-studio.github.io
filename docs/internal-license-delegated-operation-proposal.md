# 自社ライセンスは「組織のもの」として運用し、あなたを単一障害点にしない

> **推奨結論**：ライセンス、案件、メンバーをあなた個人に紐付けない。最初はあなたが組織管理者として開始するが、実運用に入る前にもう1人以上の組織管理者を追加する。案件ごとにも複数の編集者を置き、作成者が不在でも案件を継続できる状態を標準にする。

| 役割の層 | 役割名 | 主な責任 | 人数の推奨 |
| --- | --- | --- | --- |
| 組織 | 組織管理者 | ライセンス、案件作成、組織管理者の追加、全案件の引継ぎ | 最低2人、推奨3人 |
| 案件 | 編集者 | タスク・日程の編集、案件メンバー招待、共有URLの発行 | 各案件2人以上 |
| 案件 | 閲覧者 | 案件と変更ログの確認 | 必要な人数 |
| 運営 | サービス運営者 | 組織の復旧支援、契約・障害対応 | 通常の案件内容は閲覧しない |

**組織管理者**は、案件内の「編集者」「閲覧者」とは別の役割である。案件操作をする人の役割は、引き続き編集者と閲覧者だけにする。

## 1. 自社へライセンスを付与する初回フロー

### 1.1 開始時はあなたが組織管理者になる

ライセンスを自社へ付与するとき、運営者は自社用の組織を1つ作る。最初の組織管理者として、あなたのメールアドレスを登録する。あなたは初回だけ組織の入口を開く人であり、すべての案件の恒久的な担当者ではない。

  A[運営者が自社組織を作成] --> B[あなたを初期組織管理者に登録]

  C --> D[案件を作成]
  D --> E[案件ごとに編集者を2人以上追加]
  E --> F[閲覧者URLを必要に応じて発行]
