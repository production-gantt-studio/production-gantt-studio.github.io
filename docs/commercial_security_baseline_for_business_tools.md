# 販売する業務支援ツールの共通セキュリティ基準

> **適用判断**：この基準は、Manus、Claude、または人が作る業務支援ツールに共通適用する。顧客へ販売、外部スタッフへ共有、個人情報・案件情報・見積情報を保存する前に、少なくとも「販売前必須」の制御と証跡を満たす。

## 1. 基準の位置づけ

この基準は、OWASP ASVSをアプリケーション制御の確認軸、NIST SSDFを開発・脆弱性対応の確認軸として使う内部ベースラインである。[1] [2] SOC 2、ISO 27001、ISMS、個人情報保護法、顧客固有の契約条件を自動的に満たすと主張するものではない。調達先が独自要件を持つ場合は、この基準へ差分を追加する。

### 費用・API利用の事前警告

標準構成は、利用者のAPIキー入力、利用者ごとの従量課金、外部サービス契約を必要としない。販売側または利用者側にAPI利用、保存容量、定期実行、外部サービスの費用が発生する可能性を持つ機能は、設計・実装の前に必ず明示する。費用の負担者、発生条件、上限、代替案を販売責任者が承認しない限り、標準構成へ含めない。

自動バックアップは保存容量・定期実行の費用が販売側へ発生し得るため、標準構成から除外する。標準の復旧手段は、30日間のアーカイブと、案件責任者が書き出すJSONとする。詳しい扱いは [データ保存・復旧ガイド](./data_retention_and_recovery_guide_2026-08-20.md) を正とする。

### リリース区分

| 区分 | 利用範囲 | 許容条件 |
|---|---|---|
| 開発 | 開発者・固定のテストデータ | 本番個人情報・顧客機密を入れない。 |
| パイロット | 管理された少人数の実案件 | P0制御、依存関係監査、権限・保存・共有の手動受入を満たす。 |
| 販売 | 複数顧客・継続運用 | 本表の販売前必須、運用証跡、復旧、事故対応、第三者レビューを満たす。 |

## 2. 販売前必須コントロール

| ID | 分類 | 販売前必須の要件 | 必要な証跡 |
|---|---|---|---|
| SEC-01 | 資産・責任 | システム所有者、セキュリティ責任者、データ分類、外部サービス一覧を記録する。 | 台帳、責任者、レビュー日。 |
| SEC-02 | 認証 | すべての編集操作を認証済みの利用者へ限定する。パスワード不要方式では、メール確認など本人性を確認する。 | 認証フロー試験、セッション設定。 |
| SEC-03 | セッション | `HttpOnly`、`Secure`、適切なSameSite、短い通常有効期間、最大有効期間、ログアウト・失効を実装する。 | Cookie検査、失効・再認証試験。 |
| SEC-04 | 認可 | すべての読取・更新・削除をサーバー側で所有者、メンバー、役割、組織に照らして判定する。 | IDOR／権限昇格の自動・手動試験。 |
| SEC-05 | テナント分離 | 販売版の全データ、キャッシュ、ストレージ、ログを組織文脈で分離する。クライアント入力の組織IDを信用しない。 | テナント越境試験、DB・キャッシュ設計書。 |
| SEC-06 | 共有 | 共有URLは高エントロピーのトークンを用い、DBにはハッシュを保存する。期限、停止、再発行、アクセスログを持つ。 | 期限切れ・停止・他案件非表示の試験。 |
| SEC-07 | CSRF・HTTP | 更新操作をCSRFから保護し、TLS、CSP、HSTS、クリックジャッキング防止、MIME sniffing防止、許可Originを設定する。 | ヘッダー検査、クロスサイト更新拒否試験。 |
| SEC-08 | 入力・出力 | すべての境界で入力形式・長さを検証し、HTML・URL・CSV・PDFへ出す値を文脈に応じて安全に扱う。 | XSS・CSV式・大きな本文の試験。 |
| SEC-09 | レート制限 | ログイン、招待、共有、検索、更新APIに、利用者・IP・組織単位の上限を設ける。 | 429応答、再試行時間、負荷試験。 |
| SEC-10 | 依存関係 | 毎リリースで実行時依存を監査し、既知の高・中重大度を原則0件とする。例外は期限付きで承認する。 | 監査結果、例外台帳、更新PR。 |
| SEC-11 | ログ・監視 | 認証失敗、認可拒否、権限変更、招待、共有トークンの発行・停止、破壊的操作を記録する。機密トークン・パスワードをログに出さない。 | ログ例、保持期間、アラート設定。 |
| SEC-12 | バックアップ・復旧 | 費用を承認した自動バックアップを採用する場合は、暗号化、復旧目標、復旧手順、定期復旧演習を持つ。標準構成では、30日間アーカイブ、案件責任者のJSON書き出し、復旧手順を持つ。 | 採用方式、直近の復旧確認記録。 |
| SEC-13 | インシデント対応 | 連絡責任者、初動、顧客連絡、証跡保全、脆弱性修正のSLAを定義する。 | 手順書、連絡網、演習記録。 |
| SEC-14 | プライバシー | 保存する個人情報、利用目的、保持期間、削除・エクスポートの扱い、委託先を明示する。 | データ台帳、プライバシー通知。 |

## 3. 推奨の強化コントロール

| ID | 要件 | 適用する場面 |
|---|---|---|
| SEC-15 | 管理者・請求・組織変更にMFAまたは再認証を要求する。 | 顧客の管理者が増える時。 |
| SEC-16 | SAST、DAST、秘密情報スキャン、SBOMをCIへ組み込む。 | 継続的に販売・更新する時。 |
| SEC-17 | 第三者または独立チームによるペネトレーションテストを行う。 | 大口顧客、契約・調達要件がある時。 |
| SEC-18 | ストレージに組織・案件単位の短期署名URL、ファイル型検査、マルウェア対策を入れる。 | 添付・素材アップロードを始める時。 |
| SEC-19 | 管理操作に二者承認、操作理由、改ざん耐性のある監査ログを持つ。 | 金銭・個人情報・大量削除を扱う時。 |

## 4. AIへ渡すセキュリティ実装プロンプト

以下を、ManusまたはClaudeへの新規ツール依頼に追加する。

```text
## セキュリティ基準
このツールは販売・外部共有を想定する業務支援ツールです。
docs/commercial_security_baseline_for_business_tools.md を設計・実装・受入の必須基準として扱ってください。

実装を始める前に、次の表を提出してください。
1. 扱うデータと分類（公開／社内／顧客機密／個人情報）
2. 利用者・役割・サーバー側の認可規則
3. 組織・案件・共有の分離方法
4. 保存先、バックアップ、削除・アーカイブの扱い
5. 依存関係、外部サービス、秘密情報の扱い
6. 各SEC-IDへの対応状況、未実装、実装順
7. 販売側・利用者側に発生し得るAPI利用、保存容量、定期実行、外部サービスの費用と、追加費用なしの代替案

禁止事項：
- クライアントが送る組織ID・役割・案件IDだけを信頼してデータを返すこと。
- 閲覧者の編集操作を画面から隠すだけで、API更新を許すこと。
- Base64や難読化を暗号化・アクセス制御として扱うこと。
- 共有URLを無期限・停止不能・無監査のまま販売版に使うこと。
- 既知の高・中重大度の依存脆弱性を理由・期限・承認なしで残すこと。
- APIキー入力、利用者ごとの従量課金、追加費用が発生し得る外部サービスを、費用の負担者・発生条件・代替案を説明せずに標準機能へ含めること。
- 型検査、依存関係監査、権限試験、共有試験、ビルド、モバイル確認なしに販売可能と報告すること。

最終報告には、SEC-01からSEC-14の対応表、テスト結果、監査結果、残るリスク、販売を止める条件を必ず含めてください。
