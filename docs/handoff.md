# Production Gantt Studio — 引き継ぎ手順書（2026-08-20 改訂版2）

## これは何か

Production Gantt Studio の現行ソース（Claudeプロジェクトに添付された統合実装資料バンドルに収録された212ファイル）を、実際に起動・検証可能な状態へ復元したものです。機能・画面・保存・権限・セキュリティは、基本的に元のソースからそのまま復元していますが、2026-08-20にRikuからの受入保留・限定修正指示を2回受け、(1) 認証済み案件のアーカイブをサーバー側DB管理に変更、(2) 壊れたロゴ・背景画像表示をCSSのみの代替に置き換え、(3) 未ログイン時の案件一覧に動画・イベント・グラフィックの3サンプルすべてを表示、(4) サーバー側アーカイブのDB変更を適用するための移行設定（drizzle.config.ts・移行ファイル・実行コマンド）を追加、の4点を実装しています。詳細は下記「今回の限定修正」を参照してください。それ以外の独自の仕様変更は行っていません。

詳しい仕様の根拠・差分・受入証跡は、あわせて提出した「仕様凍結パッケージ」と「最終報告（改訂版2）」を参照してください。

## ローカル起動手順

```bash
# 1. 依存関係のインストール
pnpm install

# 2. 型検査
pnpm check

# 3. 単体テスト
pnpm test

# 4. 開発サーバー起動（http://localhost:3000）
pnpm dev

# 5. 本番ビルド
pnpm build

# 6. 本番モードで起動
pnpm start
```

## データベース移行（サーバー側アーカイブ用の `archivedAt` 列を適用する場合）

`DATABASE_URL` を実際のMySQL接続文字列に設定した状態で、以下のどちらかを実行してください。SQLを手で書く必要はありません。

```bash
# ケースA：このアプリのために新しく作った、空のデータベースの場合
pnpm db:migrate

# ケースB：このアプリが既に使っている、既存のデータベースの場合（本番はこちら）
pnpm db:baseline   # 1回だけ実行：既存のテーブルはそのまま、何も変更しません
pnpm db:migrate    # archivedAt列とインデックスだけを追加します
```

`pnpm db:baseline` は、`drizzle/migrations/0000_baseline_existing_schema.sql`（今のデータベースに既にあるはずのテーブル構成の記録）を「適用済み」として記録するだけで、実際にはSQLを一切実行しません（テーブルを作り直したりしません）。`pnpm db:migrate` は、その後に必要な差分（`archivedAt`列の追加）だけを実行します。`pnpm db:baseline` は一度実行すると自動的に二重実行を防止します（既に記録済みなら何もしません）。

この一連の手順は、本セッション内で用意した検証用MySQL互換データベース（MariaDB）で実際に動作確認済みです（既存データが保持されたまま`archivedAt`列が追加されることを確認）。詳細は最終報告（改訂版2）を参照してください。

## 動作に必要な環境変数（`.env` に設定、すべて任意）

| 変数名 | 用途 | 未設定時の挙動 |
|---|---|---|
| `DATABASE_URL` | MySQL接続文字列 | 未設定でもアプリは起動する。ログイン後の保存機能・招待・共有はDB接続が必要なため、これらの操作時にエラーメッセージが表示される |
| `OAUTH_SERVER_URL` / `VITE_APP_ID` | ログイン基盤への接続 | 未設定だとログインができない（未ログイン状態のLocalStorage動作は可能） |
| `JWT_SECRET` | セッションCookieの署名鍵、監査ログのIPハッシュ鍵 | 未設定だとIPハッシュがnullになる、セッションの安全性が下がるため本番では必須 |
| `OWNER_OPEN_ID` | 初回管理者権限の自動付与先 | 未設定だと手動でDB上のroleを`admin`にする必要がある |
| `BUILT_IN_FORGE_API_URL` / `BUILT_IN_FORGE_API_KEY` | （2026-08-20時点、未使用）旧ホスティング基盤経由の画像配信用。ロゴ・背景画像はCSSのみの代替に置き換え済みのため、この変数は現在参照されていません |

## 今回の再実装で判明した既知の制限（差分表を参照）

1. **依存パッチ欠落**：`package.json` が参照していた `patches/wouter@3.7.1.patch` が資料一式に含まれていなかったため、`patchedDependencies` の指定を外してインストールしています。型検査・テスト・ビルドはすべて合格していますが、元のパッチの意図（`wouter`の特定バージョンの不具合修正等）は不明です。元のパッチファイルがあれば提供してください。
2. **ビルド用 `client/index.html` を復元**：資料バンドルの収録ファイル一覧に含まれていなかったため、標準的なVite雛形として最小限の内容で作成しました（独自ロジックは含みません）。

## 今回の限定修正（2026-08-20、Rikuからの受入保留・限定修正指示への対応、計2回）

1. **サーバー側アーカイブ**：ログイン済み・DB保存中の案件の「アーカイブ」操作を、ブラウザのLocalStorageのみの表示制御から、**サーバーDB（`projects.archivedAt`列）で30日間保持・復元できる方式**に変更しました。権限（owner/admin=アーカイブ可、editor以上=復元可、viewer=不可）・組織分離・共有URLの閲覧専用は維持しています。定期実行や有料サービスは追加せず、通常の一覧・アーカイブ取得のタイミングで期限切れ（30日超過）案件を安全に削除する遅延処理方式です。詳細は仕様凍結パッケージ差分表2.5、最終報告（改訂版2）2章参照。
2. **壊れたロゴ・背景画像の除去**：`/manus-storage/...`への画像参照（実体ファイル・接続情報が資料に含まれていなかったもの）をすべて削除し、外部API・有料サービス・未配布URLを使わないCSSのみの代替（「PG」モノグラム＋グラデーション背景）に置き換えました。詳細は仕様凍結パッケージ差分表2.6、最終報告（改訂版2）3章参照。
3. **未ログイン時の案件一覧に3サンプルすべてを表示**：`client/src/pages/ProjectIndex.tsx`の初期シードデータに「動画案件サンプル」が含まれておらず、未ログイン時の案件一覧に「イベント案件サンプル」「グラフィック案件サンプル」の2件しか表示されていませんでした。「動画案件サンプル」（クライアント名は他の2件と同じく「Sample」）を追加し、3件すべてが表示・閲覧できることを確認しました。詳細は仕様凍結パッケージ差分表2.7、最終報告（改訂版2）2章参照。
4. **サーバー側アーカイブ用の移行設定を追加**：`drizzle.config.ts`（新規）、`drizzle/migrations/0000_baseline_existing_schema.sql`（新規、既存スキーマの記録用）、`drizzle/migrations/0001_project_archive.sql`（再生成、`archivedAt`列追加）、`scripts/db-baseline.ts`（新規、既存データベースへの安全な適用手順）、`package.json`の`db:generate`/`db:baseline`/`db:migrate`スクリプトを追加しました。利用者がSQLを手入力したり、APIキーを入力したり、有料サービスを契約したりする必要はありません。上記「データベース移行」節を参照してください。

## 実案件パイロットで確認すべきこと

- 実際のOAuthログイン基盤に接続した状態での、管理者1名・編集者1名・閲覧者1名による招待・編集・保存・共有・アーカイブ・復元・モバイル閲覧の受け入れ確認。本サンドボックス環境には`OAUTH_SERVER_URL`が設定できないため、これは未確認のままです（コードレビューとモックテストでの検証にとどまっています）。具体的な確認手順は最終報告（改訂版2）7章に記載しています。
- データベース移行（`pnpm db:baseline` → `pnpm db:migrate`）自体は、本セッション内で構築した検証用MySQL互換データベース（MariaDB）に対して実際に実行し、既存データを保持したまま`archivedAt`列が追加されることを確認済みです。ただし、これは本番のMySQLそのものではないため、実際の本番データベースに対しても、初回のみ実案件パイロットの一環として（または別途）一度実行し、結果を確認してください。
