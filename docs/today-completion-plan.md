> **判断**：今日公開する対象は、現行のガントチャートを安定化した**単一案件・ブラウザ保存版**に限定する。メール認証、組織、編集者、閲覧者、ライセンスは、同じ画面設計を引き継ぐ**次の製品版**として実装する。認証・マルチテナントを未実装のまま「社外メンバーが編集できる完成版」として公開しない。

## 2. 今日中に終える順番

### P0：アプリを壊れていない状態に戻す

最初に、`Home.tsx` の構文エラー記録を開発サーバーから消す。型検査だけで完了としない。ブラウザで案件を開き、タスク追加、詳細タスク追加、日程移動、フェーズ編集、共有、PDF出力を実際に操作する。

| 完了条件 | 確認方法 |
| --- | --- |
| 初回表示でエラーが出ない | デスクトップとモバイルで案件を開く。 |
| データが失われない | 既存案件を更新後も開く。JSONを書き出し・読み込みする。 |
| 主要操作が戻せる | タスク作成、詳細タスク、フェーズ、日程の変更を確認する。 |
| 共有が分離される | 共有URLでは編集操作と他案件導線が出ないことを確認する。 |

### P1：現行画面を「案件単位」に整理する

Today画面は作らない。公開版の入口は案件一覧にし、案件を開いた後は `概要 / タスク / 日程 / 変更の記録` の4画面に整理する。既存機能は削らず、置き場所を変える。

| 画面 | 今日の作業 | 公開の完了条件 |
| --- | --- | --- |
| 案件一覧 | 自分の案件を選ぶ入口を作る。 | 初見の人が案件を開ける。 |
| 概要 | その案件の期限、未定、確認待ち、最近の変更を置く。 | 他案件の情報を混ぜない。 |
| タスク | 親子タスク、重要、担当、日程未定を置く。 | タイトルだけでタスクを作れる。 |
| 日程 | 日次・月次・PDF・重要日を置く。 | 日程変更の影響が見える。 |
| 変更の記録 | 現行は将来仕様の導線として扱う。 | 未実装なら「準備中」と明示する。 |

### P2：公開用の言葉と限界を固定する

公開版では、未実装の認証や組織機能を実装済みのように見せない。共有ボタンには「閲覧用リンク」と表示し、ログイン不要であること、リンクを知る人が閲覧できることを出す。

| 表現 | 今日の公開版 | 次の製品版 |
| --- | --- | --- |
| 編集者 | 画面上の担当者情報。権限ではない。 | メール認証済みの編集権限。 |
| 閲覧者 | 閲覧用URLを開く人。 | ゲストURLの閲覧者。 |
| 案件一覧 | このブラウザに保存した案件。 | 自分が作成・招待された案件だけ。 |
| 変更の記録 | ローカル更新時刻。 | 誰が何を変えたかの永続ログ。 |

### P3：公開前の最終検証

| シナリオ | 操作 | 合格条件 |
| --- | --- | --- |
| 新しい利用者 | 空の状態から案件とタスクを作る | 迷わずタスクを1件作れる。 |
| 制作PM | 日程を変更し、後続工程を確認する | 変更の影響が期待どおり見える。 |
| 協力会社 | 共有URLを開く | 対象案件だけを閲覧でき、編集できない。 |
| クライアント | 月次PDFを書き出す | A4横向きで読める。 |
| モバイル利用者 | 案件、タスク、日程を確認する | サイド操作レールとアナウンスが潰れない。 |
| データ保全 | JSONを書き出し、読み込む | 主要データが復元できる。 |

### P4：安定版を保存して公開する

すべてのシナリオを通過した後に、安定版チェックポイントを保存する。自動公開が有効なため、チェックポイントが公開版になる。公開直後に、共有URLとPDF出力をもう一度確認する。

## 3. 次の製品版へ送るもの

メール認証・組織・ライセンスは、今日のガント安定化と同時に無理に入れない。画面だけ整えても、組織をまたぐデータ隔離や権限判定が甘ければ、販売できる状態にはならない。

| 次の製品版の順番 | 実装対象 | 完了条件 |
| ---: | --- | --- |
| 1 | フルスタック化、DB、認証 | マジックリンクで編集者がログインできる。 |
| 2 | 組織・案件メンバー | 自分が作成・招待された案件だけが一覧に出る。 |
| 3 | 編集者・閲覧者 | 編集者だけが変更し、閲覧者は案件と変更ログだけを見られる。 |
| 4 | 変更ログ・共有失効 | 誰が何を変えたか、いつ共有を止めたかを残す。 |
| 5 | ライセンス・組織管理者 | 会社単位で編集者枠と管理者を運用できる。 |
